# 📊 TrendBite — 신메뉴 수익성 시뮬레이터

> 소자본 외식업 사장님을 위한 **트렌드 · 입지 · 재무 통합 분석 서비스**

신메뉴를 들일 때 사장님은 세 가지를 따로따로 판단합니다. 유행을 얼마나 탈지는 SNS와 감에 기대고, 수익성은 메모장이나 계산기로 대충 셈하고, 우리 동네에 맞는지는 판단할 근거가 거의 없습니다.

TrendBite는 메뉴명, 매장 주소, 원가와 고정비를 한 번만 입력하면 이 세 가지를 함께 분석합니다. 결과는 **종합 점수, 도입 판정, 위험 요인이 담긴 AI 리포트**로 제공됩니다.

- 📅 **기간** : 2026년 상반기 (서울여자대학교 소프트웨어융합학과 졸업 프로젝트)
- 🏆 **2026 한국디지털콘텐츠학회 하계종합학술대회 및 대학생논문경진대회 동상**
  - 「트렌드바이트: 소상공인 신메뉴 도입 의사결정 지원을 위한 트렌드와 입지 및 재무 데이터 통합 분석 시스템」

<br>

## 🔍 문제 정의 — 사장님 설문조사

서울여대 인근 공릉동의 카페·식당 사장님 7명을 직접 만나 설문했습니다.

- **86%** : 신메뉴를 고를 때 "유행이 얼마나 지속될지"를 매우 중요하게 고려합니다.
- **71%** : 메뉴 수익성을 체계적으로 계산하지 않거나, 아예 계산하지 않습니다.
- **100%** : 신메뉴 결정의 1순위 기준으로 "우리 매장 고객층과의 적합성"을 골랐습니다.

설문 결과 사장님들이 원하는 것이 TrendBite의 세 모듈(트렌드 수명 분석, 영업이익 시뮬레이션, 입지 보정)과 맞아떨어진다는 것을 확인했습니다.

## ✨ 주요 기능

| 기능 | 설명 |
|---|---|
| 📈 **트렌드 수명주기 분석** | 네이버 데이터랩 검색량으로 메뉴의 단계(도입·성장·성숙·쇠퇴)를 분류합니다. 추세 검정을 먼저 하고 Bass 모델을 적용하는 계층 구조를 썼고, DTW로 과거 유행 메뉴(탕후루, 달고나커피 등) 가운데 추이가 가장 비슷한 메뉴를 찾아 보여줍니다. |
| 📍 **입지 보정계수** | 매장 주소를 좌표로 바꾼 뒤 서울시 상권(약 1,650곳)과 매칭합니다. 상권의 유동인구, 추정매출, 경쟁점포 수로 0.8~1.2 사이의 보정계수를 계산합니다. |
| 🧮 **재무 시뮬레이션** | 원가를 재료비, 인건비(주휴·야간수당 반영), 간접비로 나눠 계산합니다. 공헌이익을 바탕으로 월 영업이익, 이익률, 일일 손익분기 판매량을 구합니다. |
| 🔄 **실판매 보정** | 판매를 시작한 뒤 일별 판매량이 5일 이상 쌓이면 지수 가중 이동 평균(α=0.3)으로 예상 판매량을 보정합니다. |
| 🤖 **AI 종합 리포트** | 세 분석 결과를 종합 점수와 4단계 판정(도입 권장 · 신중 검토 · 불확실 · 보류)으로 정리하고, 위험 요인과 함께 리포트로 만듭니다. |

<br>

## 🏗 시스템 구조

```
[ Next.js 프론트엔드 ]
          │  메뉴 · 주소 · 원가 · 고정비 입력
          ▼
[ Main Server : Spring Boot · MySQL ]   ← 이 저장소
   ├─ Finance   재무 계산 · 수익 시뮬레이션 · 실판매 보정
   ├─ Location  입지 보정계수 (서울시 상권분석 · 소진공 API)
   └─ Trend     에이전트 서버 연동
          │
          ▼
[ Agent Server : FastAPI · LangGraph ]
   ├─ 트렌드 수명주기 분류 · DTW 패턴 매칭
   ├─ 종합 점수 · 도입 판정
   └─ 리포트 생성 (초안 → 검토 → 수정, 최대 3회 반복)
          │
          ▼
[ 경량 LLM : Qwen2.5-1.5B · LoRA 미세조정 · INT4 양자화 · vLLM ]
```

- **수치와 문장 생성을 분리했습니다** : 모든 점수와 판정은 규칙에 따라 미리 계산하고, 언어 모델은 그 결과를 문장으로 풀어 쓰는 역할만 맡습니다. 그래서 모델이 잘못된 내용을 지어내도 수치에는 영향을 주지 않습니다.
- **리포트용 모델을 직접 경량화했습니다** : 합성 데이터 300건으로 미세조정하고 양자화한 모델을 직접 서빙해, 외부 API에 의존하는 정도와 응답 지연을 줄였습니다.

<br>

## 📊 성과 (논문 실험 기준)

- **수명주기 분류 정확도 86.1%** : 외식 메뉴 18종의 평가용 구간 223개 기준입니다.
- **리포트 생성 시간 약 82.3% 단축** : 언어 모델 1회 호출 시간이 외부 API 4.74초에서 직접 구동 모델 0.84초로 줄었습니다.
- **실제 메뉴 적용** : 우베라떼, 소금빵, 바스크치즈케이크로 사례 시뮬레이션을 해 봤습니다. 수익성은 좋지만 유행 지속성이 약한 경우처럼 두 기준이 엇갈리는 위험 요인을 구분해 낼 수 있었습니다.

> ⚠️ 위 결과는 시스템이 구현 가능한지와 주요 기능이 의도대로 동작하는지를 확인한 것입니다. 실제 판매 성과와 비교해 수익성 예측 정확도를 검증한 것은 아닙니다.

## 📡 API (Main Server)

| 도메인 | Method | URL | 설명 |
|---|---|---|---|
| Finance | `POST` | `/api/v1/finance/calculate` | 재무 계산 |
| Finance | `POST` | `/api/v1/simulation/run` | 영업이익 시뮬레이션 |
| Finance | `POST` | `/api/v1/sales/record` | 실판매 기록 저장 |
| Finance | `GET` | `/api/v1/sales/correction/{menuId}` | 보정된 예측값 조회 |
| Location | `POST` | `/api/v1/location/analyze` | 입지 분석 |
| Location | `POST` | `/api/v1/admin/location/cache/invalidate` | 입지 캐시 초기화 |
| Trend | `POST` | `/api/v1/trend/analyze` | 트렌드 분석 |
| Trend | `GET` | `/api/v1/trend/popular` · `/patterns` · `/lifecycles` | 인기 키워드 · 과거 패턴 · 수명주기 |
| Analysis | `POST` | `/api/v1/analysis/run` | 통합 분석 실행 |
